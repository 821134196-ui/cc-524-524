# 🌿 企业导师配对系统（Mentor Match）

新员工导师申请、主管配对、按次记录目标与反馈的本地一体化系统。
**零第三方依赖**，仅用 Python 3 标准库 + SQLite。

## 一条命令启动

```bash
./run.sh            # 默认端口 8000，自动重置演示数据
./run.sh 8123       # 指定端口
# 或
python3 main.py --fresh --port 8000
```

启动后打开 http://127.0.0.1:8000/login ，选择演示身份登录。

## 六个交付页面

| 页面 | 路径 | 说明 |
|---|---|---|
| 导师目录 | `/` | 导师姓名旁直接展示**擅长领域标签**与**近 30 天剩余名额**（0 名额灰点） |
| 匹配申请 | `/apply` | 员工选择希望提升的岗位技能与可交流时段（多工作日 × 时间段） |
| 时段安排 | `/schedule` | 按身份查看我的辅导计划、已落定时段；员工确认时段后计划开始 |
| 辅导纪要 | `/plan?id=` | **公开目标按目标时间线**展开 + 进展记录；**🔒 私密反馈区域与公开目标清晰分区** |
| 换导师 | `/transfer` | 员工发起，主管审批；通过后旧计划废弃、释放时段名额并生成新计划 |
| 结项审核 | `/review` | 主管工作台：配对、换导师审批、提前结项审核、导师离职处理 |
| 消息回执 | `/messages` | 模拟消息适配器，所有通知落库为 SENT/READ 回执 |

## 角色与流转

- **员工**：提交匹配申请 → 确认时段 → 记录公开目标/进展与**本人**私密反馈 → 可申请换导师/提前结项。
- **导师**：填写擅长领域、每月可带人数、所属部门与是否接受跨部门；写纪要时作者身份由登录态强制，**不能替员工提交反馈**。
- **主管**：确认配对；审批换导师与提前结项；处理导师离职。审批权限限定在员工或导师所属部门（跨部门主管回避）。

异常流转均有明确去向：

- **导师离职**：账号停用、目录移除、进行中计划自动生成"离职改派"申请并通知员工；再配对该导师被拦截。
- **跨部门回避**：导师 `accepts_cross=0` 时，跨部门员工的配对与改派均被拒绝（`CROSS_DEPT`）。
- **时间冲突**：配对时员工时段与导师既有安排**全部**冲突才拒绝；部分冲突放行，员工确认时只落定无冲突时段。
- **员工换导师**：审批通过即废弃旧计划（释放 `schedule_slots` 与名额），生成指向前序计划的新 PENDING 计划。
- **长期未开始**：PENDING 超 5 天，进程内守护线程（每 60 秒）扫描并给员工发 `STALE_PENDING` 提醒，同一计划只提醒一次。
- **计划提前完成**：任一方发起 → 部门主管审核；批准后计划 COMPLETED、时段释放、禁止再写纪要。

## 容量竞争的并发保证

配对的关键段为 `BEGIN IMMEDIATE` 事务：在写锁内完成"读剩余名额 → 插入计划"，
SQLite（WAL + `busy_timeout=15s`）串行化两个主管的并发配对，
**同一导师同一时间段名额不会被重复占用**，第二个事务拿到锁后若发现名额已满则回滚并返回 `CAPACITY_FULL`。
测试 `TestCapacityRace.test_concurrent_match_no_overbook` 以双线程屏障同时发起配对验证。

## 私密字段权限

私密反馈（`feedback_private`）仅 **当事员工、当事导师、双方所属部门的授权主管** 可见；
其他员工或外部门主管看不到内容，页面显示隔离提示，且每次查看（允许/拒绝）都写入
`access_log` 审计。附件下载适用同样规则。

## 数据与存储

- SQLite：`data/mentor.db`（可用环境变量 `MENTOR_DB_PATH` 覆盖；测试各自用临时库）。
- 本地虚构附件：`data/attachments/`（`MENTOR_ATTACH_DIR` 可覆盖），页面可一键生成演示文件并下载。
- 提醒：进程内 daemon 线程（`app/reminders.py`），无外部调度器。
- 消息：模拟适配器（`services.MockMessageAdapter`）落库 `messages`。

## 测试

```bash
python3 -m unittest tests.test_domain tests.test_web   # 25 个用例
# 端到端走查（先启动服务，再运行；走查会改变数据，需 --fresh 重启）
python3 main.py --fresh --port 8123 &
python3 tests/e2e_walk.py                              # 29 项检查
```

覆盖：并发容量竞争、跨部门回避（配对/换导师/主管越权）、私密字段权限与审计、
作者身份绑定（导师不能代员工）、提前结项、时间冲突（全冲突/部分冲突/确认时拦截）、
导师离职改派、长期未开始提醒去重。
